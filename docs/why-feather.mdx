Python has a long history in web development. Flask and Django powered countless
applications through the 2010s. Then the SPA era arrived, and "modern" web development
came to mean writing Python APIs that served JSON to JavaScript frontends.

That split left a gap. Python developers who wanted full-stack productivity had two
choices: adopt the JavaScript ecosystem wholesale, or stay with Django's monolithic
approach, which had not evolved much for the new era. Ruby developers had Rails with
Hotwire. PHP developers had Laravel with Livewire. Both embraced server rendering while
adding modern interactivity.

Feather fills that gap for Python. It gives you authentication, admin panels, file
storage, background jobs and a component system without assembling them yourself. The
frontend is server-rendered HTML enhanced with HTMX and small JavaScript islands. There
is no virtual DOM, no hydration, and no deciding which side of a boundary a component
runs on.

## How other frameworks approach this

<AccordionGroup>
  <Accordion title="Rails and Laravel" icon="gem">
    They established the batteries-included approach, handling auth, database migrations,
    background jobs and asset compilation in one package. Feather works the same way,
    using Python and current tooling: Vite 7, Tailwind CSS and HTMX.
  </Accordion>
  <Accordion title="Next.js" icon="triangle">
    It brought React to the server with a strong developer experience. You still manage
    React's complexity, though: state management, hydration mismatches, and decisions
    about where each piece of code runs. Feather avoids that by keeping JavaScript
    minimal and optional.
  </Accordion>
  <Accordion title="Django" icon="leaf">
    Still capable, but heavy for many projects. Its template language is limiting, the
    admin is rigid, and modern frontend tooling takes real configuration to add.
  </Accordion>
</AccordionGroup>

## Conventions make AI assistance work

Predictable patterns are what let an assistant produce working code. Feather fixes where
files go, how services are shaped, and what components look like, so a description of the
feature you want maps onto a known structure. Work that would otherwise mean a day of
wiring up authentication, writing migrations, building UI and handling edge cases fits
into a focused session.

<Tip>
  Conventions only help if they are checkable. See [AI assistants](/ai-assistants) for the
  four commands an assistant can run to verify its own work.
</Tip>

## Opinionated, but extensible

Feather picks defaults: Google OAuth for auth, Tailwind for styling, PostgreSQL for
production data. Fewer decisions up front means you ship sooner.

The abstractions stay open. The storage interface covers local files and Google Cloud
Storage, the job queue runs in-process or on Redis, and you can add other providers as
your needs change.
