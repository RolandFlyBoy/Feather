Feather works with any AI coding assistant, and is tuned for
[Claude Code](https://claude.ai/code).

## Two files, one set of rules

Every scaffolded project contains a `CLAUDE.md` and an `AGENTS.md` with identical
content, written together so they cannot drift. `AGENTS.md` is the vendor-neutral name
other tools look for. Both carry the full rules rather than one linking to the other,
because an assistant that has to follow a link often does not.

A `.claude/settings.json` sits alongside them, pre-approving the read-only commands an
assistant needs.

<Note>
  These files are a starting point. Add your own domain rules and preferences as the app
  grows.
</Note>

## Why the conventions are strict

[`feather check`](/tooling/check) enforces the rules in `CLAUDE.md` and exits non-zero on
any error, so it works as a pre-commit hook or a CI step.

Exceptions are recorded rather than hidden. A deliberately public route carries a
`# feather: public` comment in its module. When a rule is wrong about a specific line, an
inline marker silences it for that line and asks for the reason. A rule with no way to
say "not here" is one people turn off entirely.
