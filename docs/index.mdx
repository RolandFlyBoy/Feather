Feather is a full-stack web framework built on proven parts: **Flask** for the backend,
**Tailwind CSS** for styling, **HTMX** for dynamic interactions, and **vanilla
JavaScript** for complex client-side behavior.

It works with any AI coding assistant, and is tuned for
[Claude Code](https://claude.ai/code). Every project ships a `CLAUDE.md` and an identical
`AGENTS.md` describing the conventions to follow. `feather check` enforces the ones that
can be enforced, so an assistant can check its own work instead of guessing.

## What's included

Every feature below is optional. Turn it on during project creation, or add it later.

| Feature | Options |
| --- | --- |
| **Authentication** | Google OAuth with session management, approval workflow |
| **User management** | Admin panel for approvals, roles, suspension |
| **Multi-tenancy** | Domain-based or individual tenants (B2B and B2C) |
| **Background jobs** | Thread pool with concurrency control, or RQ on Redis |
| **Caching** | Memory or Redis |
| **File storage** | Local filesystem or Google Cloud Storage |
| **Email** | Resend for transactional email |
| **Dark mode** | Cookie-persisted toggle on every page, including admin |
| **Security headers** | CSP, HSTS, X-Frame-Options, Referrer-Policy in production |
| **Rate limiting** | In-memory, or Redis for distributed |
| **Events** | Pub/sub with sync and async listeners |
| **Error logging** | Database-backed, tenant-scoped |
| **Health checks** | `/health`, `/health/live`, `/health/ready` |
| **Request tracking** | Unique request IDs, JSON logging |

## The three-layer frontend

Feather builds UIs in three layers, each solving a different problem. Start with
components for anything static. Reach for HTMX when you need server data without a page
reload. Use islands only when you need state on the client. Most features need nothing
past the first two.
